# adopt-baseline

## Scope

One repository, once. This adopts conventions into a project. It does not
install the machine-wide configuration; `scripts/install.sh` and
`scripts/install.ps1` in the baseline repository do that, and they are unrelated
to anything here.

## Workflow

1. Inventory what already exists before changing anything.
2. Reconcile instruction files so no existing content is lost.
3. Select the planning documents that match the repository type.
4. Decide keep-or-promote for each existing skill.
5. Wire project-local skills so both agents find them.
6. Verify each agent loads what is expected.

## 1. Inventory

```bash
ls AGENTS.md CLAUDE.md CLAUDE.local.md SPEC.md ROADMAP.md TASKS.md PLAN.md 2>/dev/null
ls -d .agents/skills .claude/skills .codex/skills 2>/dev/null
git log --oneline -5 -- AGENTS.md CLAUDE.md
```

Record which files exist and whether each carries real content or is a stub.
Report the inventory before editing.

## 2. Reconcile instruction files

Claude Code reads `CLAUDE.md` and never `AGENTS.md`, so the convention is a
repository `AGENTS.md` plus a `CLAUDE.md` containing only `@AGENTS.md`.

Handle the case that applies:

- **Neither exists.** Create `AGENTS.md` from the template and write `CLAUDE.md`
  containing the single line `@AGENTS.md`.
- **`AGENTS.md` only.** Add the one-line `CLAUDE.md`. Nothing else changes.
- **`CLAUDE.md` only, with content.** Move its content into `AGENTS.md` first,
  then replace `CLAUDE.md` with the import. Never reduce a `CLAUDE.md` to the
  import before its content is preserved somewhere.
- **Both exist with content.** Merge into `AGENTS.md`, resolving contradictions
  with the user rather than silently preferring one. Then replace `CLAUDE.md`.
- **`CLAUDE.local.md` exists.** Leave it. It is personal and usually ignored by
  Git.

If the existing `CLAUDE.md` was generated by a tool that rewrites it, such as
`rtk init`, note that the tool will recreate its block on the next run.

## 3. Select planning documents

Adopt only what the repository needs. All types take `AGENTS.md` and
`CLAUDE.md`.

| Repository type | Add |
| --- | --- |
| Product or service with staged delivery | `SPEC.md`, `ROADMAP.md`, `TASKS.md`, `PLAN.md` |
| Automation, infrastructure, or dotfiles | `TASKS.md`, and `PLAN.md` when a change is non-trivial |
| Library or single-purpose tool | `PLAN.md` only when a change is non-trivial |
| Documentation or content | none beyond the instruction files |

These are selections from one template set, not separate variants. Adapt each
adopted template to the repository and delete sections that do not apply rather
than leaving placeholders.

Do not create a document the repository has no use for. An empty `ROADMAP.md`
teaches an agent nothing and goes stale.

## 4. Keep or promote existing skills

For each skill already in the repository:

- **Keep it local** when it encodes this project's requirements, paths, or
  deployment specifics.
- **Promote it to the baseline** when the workflow is reusable across
  repositories and independent of this project. Move it to the baseline
  repository's `.agents/skills/`, add it to that repository's skill inventory,
  and remove the local copy.
- **Retire it** when the baseline already covers it. Say so rather than leaving
  a near-duplicate that competes for the same trigger.

Check that a kept skill's description does not collide with a baseline skill's
trigger. Cross-reference both descriptions when the scopes are adjacent.

## 5. Wire project-local skills for both agents

Codex reads `.agents/skills/`; Claude Code reads `.claude/skills/`. Author each
project-local skill once under `.agents/skills/` and expose it to Claude with a
single directory link rather than duplicating files.

```bash
# Linux and macOS
ln -s ../.agents/skills .claude/skills
```

```powershell
# Windows: a junction works without Developer Mode or elevation
New-Item -ItemType Junction -Path .claude/skills -Target .agents/skills
```

Add `.claude/skills` to `.gitignore` and create it during adoption. A committed
symbolic link becomes a plain text file when cloned on a Windows machine without
symbolic-link support, which breaks skill discovery silently.

Skip this step entirely when the repository has no project-local skills.

## 6. Project-scoped configuration directories

Create neither `.claude/` nor `.codex/` up front. Add a file only when the
project genuinely needs something the machine-wide baseline does not provide.

| Path | Create when | Commit |
| --- | --- | --- |
| `.claude/settings.json` | the project needs shared permissions or hooks | yes |
| `.claude/settings.local.json` | never by hand; Claude Code writes it | **no** |
| `.claude/skills/` | the project has local skills, as a link | no |
| `.codex/config.toml` | the project needs Codex settings of its own | yes |
| `.codex/skills/` | never; it is legacy | n/a |

Two asymmetries matter:

- Claude Code writes personal state into the repository.
  `.claude/settings.local.json` records permissions approved interactively and
  contains absolute paths. Add it to `.gitignore` during adoption, before it is
  created, because it appears as soon as anyone approves a permission. Codex has
  no equivalent; it keeps project trust in the machine-wide `config.toml`.
- `.codex/config.toml` is honored only in projects Codex trusts, so a setting
  placed there silently does nothing in an untrusted project.

## Safety rules

- Never reduce a `CLAUDE.md` to the import before preserving its content.
- Never overwrite an existing planning document. Merge, or ask.
- Never delete a skill without confirming the baseline covers it.
- Never commit `.claude/skills` when it is a link.
- Never commit `.claude/settings.local.json`. Ignore it before it exists.
- Keep project requirements in the project's documents, not in promoted skills.

## Validation

- `AGENTS.md` contains every instruction that previously lived in `CLAUDE.md`.
- `CLAUDE.md` contains only `@AGENTS.md`.
- Every adopted planning document describes this repository, with no leftover
  placeholder text.
- Project-local skills resolve under both `.agents/skills/` and
  `.claude/skills/`.
- `.claude/skills` is ignored by Git when it is a link.
- Each agent, asked to list its active instruction sources and skills, reports
  the repository instructions and the expected skills.
